# hountybunter Phase 5: Web UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything already in the store, visible in a browser: projects,
sessions, and notes. Plus the one write the CLI makes awkward — recording a
decision by reviewing a session that already happened, rather than by
remembering to type `hb jot` while it was happening.

**Architecture:** A local read-mostly HTTP server over the existing `core`
query API, and a client that renders it. `core` is untouched: the server
imports `openDb`, `listSessions`, `listNotes`, `searchNotes`, `writeNote`,
`indexNote`. No SQL is written in `surfaces/web`. The one write path goes
through the same `core` functions the CLI uses, so a note recorded in the
browser and a note recorded at the prompt are the same file.

**Tech Stack:** TypeScript 5, Node 22, `node:http` (zero-dependency server),
Vite + React 18 for the client, Vitest. No CSS framework.

**Spec:** `docs/superpowers/specs/2026-08-27-hountybunter-design.md` §4, §5, §13

**Approved layout:** the third mockup reviewed on 2026-09-01 — a 288px
full-height left menu that collapses to zero via an edge tab, a scene band
capped by viewport height, and the panel below switching per menu item.

## Global Constraints

- **`core` is not modified by this phase except through its own tests.** If the
  web surface needs a query that does not exist, it is added to `core` with
  tests first, exactly as `listSessions` was. (Spec §4)
- **The server binds `127.0.0.1` only, never `0.0.0.0`.** Single local user; no
  auth, and therefore no exposure. (Spec §2)
- **Read-only on source code, still.** The only files this phase writes are
  note markdown files in the store. No commits, no edits to the user's repo.
  (Spec §2)
- **SQLite stays derived and disposable.** The server never writes to the index
  except through `indexNote` after a note file is written. Deleting `index.db`
  and running `hb rebuild` must still lose nothing. (Spec §4)
- **An absent signal is rendered as absent.** A session with no timestamp, no
  title, or no task list is shown as lacking it — never defaulted, never given
  a full or empty bar. (Spec §7.4)
- **Guessed correlation is labelled guessed.** (Spec §7.4)
- **No pixel art in this phase.** The scene band renders as a plain panel;
  sprites are phase 7 and are blocked on choosing a CC0 pack. The layout must
  not assume art exists.
- **No chat, no PTY, no hooks.** Talking to Claude inside the UI is phase 6 and
  needs `node-pty`; this phase reads sessions after the fact.
- **Out of scope:** live sessions, bounties, staleness verification, Agent SDK.

## File Structure

```
core/
  src/db/query.ts                 + getSession, listActivities  (Task 1)

surfaces/web/
  package.json
  tsconfig.json
  vite.config.ts
  src/
    server/
      routes.ts                   request -> handler, no node:http types
      serve.ts                    node:http shim, binds 127.0.0.1
    client/
      main.tsx                    mount
      App.tsx                     shell: menu + panel
      api.ts                      typed fetch wrappers
      views/
        Sessions.tsx
        SessionDetail.tsx
        Notes.tsx
        Regions.tsx
      ui/
        Menu.tsx                  288px, collapse tab
        Panel.tsx
    index.html
  tests/
    routes.test.ts                handlers tested without a socket
    views/*.test.tsx
```

**Why these boundaries.** `routes.ts` maps a method plus path to a plain
`{status, body}` so every endpoint is testable without opening a port;
`serve.ts` is the only file that knows `node:http` exists and holds no logic.
The client's `api.ts` is the single place a URL string appears, so a route
rename breaks one file.

## Task 4: Recording a decision from a session

The point of the phase. A session that already happened is the input; the note
is the output; `rejected` and `evidence` are fillable here, not afterwards.

- [ ] **Step 1: Write the failing test** — `POST /api/notes` with

      file under the session's project, indexes it, and returns the note id.
      Evidence gains `session:<id>` automatically. Missing `question` or
      `chosen` returns 400 naming the missing field. The written file

## Done when

`hb web` opens a browser where every session, note, and project in the store is
visible, and a decision can be recorded from a session that already happened —
producing a markdown file indistinguishable from one `hb promote` would write.

## Deliberately not decided here

- **Which CC0 pack.** The scene band ships as a plain panel. Art is phase 7 and
  the layout must survive never getting it.
- **Whether the panel gets a chat.** Phase 6, and it needs `node-pty`, which
  §14 rates a high install-failure risk. This phase must be useful without it.
